# DDS 输出过滤操作说明

本功能只筛选正式 `FusionMultiTarget` 的目标列表，沿用原 DDS 发送方式和二进制报文头。内部航迹、态势主画面和外部 WebSocket 不过滤、不删除；不能通过此功能把“未知”类别改成“无人机”。

此副本适用于 RK3588 工程：保留 `.rk3588-env` 启动/构建流程、WebSocket 11409 端口、原有 DDS 接收监控、光电和射频类别修正，以及原有 `SB_FUSION_MIN_CONFIDENCE` 置信度策略（默认 0.05，未替换为 DGX 的固定 0.2）。本次同步只更新 Mac 本地代码，未连接或重启板端。拷贝到板端时应一并带上新增的 `configs/output_filter.yaml`、过滤模块、网页资源和接口接线文件，不能只拷贝网页。

## 启动与入口

代码更新后由操作人员按原方式启动（已有服务须先自行正常停止，避免端口冲突）：

```bash
cd /home/kylin/code/sb_fusion_2
./start_equipment_fusion.sh
```

无需重新编译 DDS 库或安装新的运行依赖。启动时会打印过滤配置路径与加载值。

打开 `http://192.168.8.76:8000/` 或 `/debug.html`，点击右下方 **DDS 输出过滤 / 阈值设置**。如果页面旧缓存未更新，请强制刷新。接口 `/api/output-filter` 可只读查看融合节点的生效值、心跳、批次计数及过滤原因。

## 默认判据

配置文件是工程内 `configs/output_filter.yaml`。也可通过环境变量 `SB_OUTPUT_FILTER_CONFIG` 指定其他配置文件；该路径必须由融合进程所在用户读写。

- 最少有效定位点数：2。
- 最低、最高水平速度：1、15 m/s（由融合状态 `vx, vy` 计算）。
- 最低相对雷达高度：30 m。
- 参考雷达：`radar_3152`，可在面板修改。

上述点数、最低速度、最高速度、相对高度四项规则，**仅在每条融合航迹建立后的 `[0,9)` 秒内生效**。这段时间任一启用规则不满足即拦截；数值等于阈值边界允许。**航迹年龄达到 9.000 秒后，四项规则全部停止拦截**，不是必须等满9秒才允许发送，也不会因前9秒不合格而永久拒绝。原有融合置信度门槛、航迹存续判断和协议容量限制仍保留。

计时起点是本系统建立融合航迹的时刻，不是雷达设备自身航迹的起点、第一次通过阈值的时刻、最后一次更新的时刻或网页打开时间。正常接入/回放按融合数据时间计算，演示模式按实际 `dt` 累计，不按帧数或浏览器墙钟估算。新报文、调参、重新启用过滤不会重启计时；航迹删除后重新起批、输入流显式重置或服务重启会重新累计；航迹合并保留较早的建立时间。缺少有效航迹年龄时，保守按筛选期检查，界面会明确提示。

在筛选期内，缺少启用规则所需的有效数值时拦截并说明原因，不用 0 补齐。满9秒后也不再因为这些过滤数值缺失而拦截；但底层定位、融合质量和协议本身的限制不变。

高度计算为 `融合目标 z_ENU - 参考雷达站址 z_ENU`。使用输入链路当时生效的雷达站址（有效设备自身 GPS 优先，否则配置回退）；不是绝对海拔，也不是相对地形高度。须保证目标与站址的高度基准一致。尚未收到参考雷达的有效站址时，不猜测站高。

点数是本融合航迹实际接受的不同观测时刻的定位更新次数，不是页面刷新次数或上游设备航迹寿命。预测、心跳、重复时间戳、设备外推以及单站纯测向均不增加计数；同一时刻多源位置只计一次，合并航迹不重复累加历史。服务/输入流显式重置或航迹重新起批后重新累计。经质量门控接受的双站交汇可计为定位更新。

## 调参和保存

1. 每一项右侧都有独立的“过滤开启 / 过滤关闭”按钮，依次控制点数、最低速度、最高速度、相对雷达高度。启动时从配置文件读取开关及阈值，不在网页中强制开启。按钮绿色为选择开启、灰色为选择关闭；只编辑不会立即改变发送结果。
2. **应用到当前运行**：融合节点确认后生效，不写文件，重启后恢复配置文件值。
3. **保存配置并应用**：同时保存四个独立开关、总开关和各阈值，校验、备份并原子替换配置，随后生效。备份在配置同目录的 `output_filter.yaml.bak-时间-编号`。保存失败不会切换运行参数，也不会假报保存成功。下次启动沿用保存值。
4. **载入已保存值**：把配置值填回表单，仍需点击“应用”才改变当前运行值。
5. **刷新生效值**：重新读取融合节点实际使用值，放弃未应用的编辑前会提示。

多个页面同时编辑时，旧版本操作会被拒绝，请刷新核对后重试。页面没有收到匹配的融合节点回执时不会宣称生效。仅应在可信调试网络使用；接口令牌和同源检查并非完整用户认证。

每项按钮下方分别显示“当前生效”和“配置保存”状态；修改未应用时另有提示。关闭某项只跳过该项判断，阈值保留，其他开启项照常检查。例如只关闭最低速度，不会关闭最高速度。总开关关闭时四项均不执行，但仍保留各自选择，重新打开总开关不会把四项强制全开。仅开启一侧速度过滤时，停用的另一侧阈值不约束输入；重新同时开启上下限时，必须满足最低速度不大于最高速度。

`configs/output_filter.yaml` 中的对应关系如下，`true` 表示开启，`false` 表示关闭（不加引号）：

```yaml
enabled: true           # 总开关
points_enabled: true    # 点数过滤
min_speed_enabled: true # 最低速度过滤
max_speed_enabled: true # 最高速度过滤
height_enabled: true    # 相对雷达高度过滤
```

手动修改 YAML 后在下次启动时读取；网页点击“保存配置并应用”则由当前融合节点写回同一配置文件，并立即更新运行值，无需为每次调参重启。配置路径以面板显示的 `config_path` 为准。

## 查看结果及限制

面板显示最近批次内部航迹数、原有输出候选数、DDS 放行数、未发送数及逐目标原因，可切换全部/仅放行/仅被过滤。新增“航迹年龄 / 筛选期”列，区分“前9秒筛选中”“筛选期已结束”。右侧 F5 等编号后的放行/拦截标记保持同步，悬停可查看年龄、阶段和原因。最多展示 100 条，批次统计为完整计数；超过原协议单包 255 目标容量也会标明。

本次9秒规则涉及 Python 融合节点，操作人员需重启融合服务后生效，仅刷新网页不够。新页面连接尚未重启的旧节点时，会明确提示“旧版全程过滤”。独立按钮更新也调整了后端单侧速度阈值校验，代码部署后需手动重启一次；以后通过界面应用/保存开关和阈值不需要重启。临时应用但未保存的数值会按既有规则在重启后恢复配置文件值；如需保留，请先自行点击“保存配置并应用”。

“发布接口返回成功”不代表下游已收到，联调时仍需在接收端监听 `FusionMultiTarget`。全部被过滤时沿用原发布器的零目标包行为，不发送这些目标条目；不新增删除指令，接收端旧航迹清理取决于其既有超时规则。

过滤不会让态势主画面的其他航迹消失，也不会改变外部 WebSocket。降低阈值后仍存在的内部航迹可沿用原融合 ID 恢复正式 DDS 输出。

这些是演示筛选规则，并非无人机识别算法：筛选期内低于最低速度的悬停、低空真实无人机也可能被过滤；存续满9秒的低速、低空非无人机目标也可能恢复输出。请结合实际数据、站址高度与下游接收结果调试。
